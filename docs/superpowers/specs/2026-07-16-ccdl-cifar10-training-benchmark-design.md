# CCDL CIFAR-10 双卡训练与通信压缩评测设计

## 目标

在 2×NVIDIA RTX 4090 D 真机环境中，公平比较原生 NCCL 梯度同步与 CCDL INT8/INT4 量化通信，回答以下问题：

1. CCDL 对纯通信延迟、有效带宽和端到端训练吞吐的影响。
2. 量化通信对训练曲线、最终分类精度和稳定性的影响。
3. 量化通信使模型达到同等精度所需 optimizer steps、epoch 和墙钟时间如何变化。
4. Top-K 离群值保留带来的精度收益是否抵得上额外元数据和 kernel 开销。

## 环境与范围

- 远端主机：`wangjun@192.168.1.100`。
- GPU：2×NVIDIA GeForce RTX 4090 D，每卡 24 GB。
- 数据集：CIFAR-10。
- 模型：CIFAR-10 版 ResNet-18，使用 3×3 stem 并移除初始 max-pool。
- 训练长度：每个配置 200 epochs、3 个随机种子。
- 本阶段不测试语言模型；语言模型评测作为后续独立阶段。

## 实验架构

主训练实验采用受控的扁平梯度同步。每个训练步骤在反向传播后把所有有效梯度复制到一个连续 buffer：

- 基线对 buffer 调用原生 NCCL `all_reduce`。
- CCDL 组对相同 buffer 调用 `qall_reduce`。
- 同步结束后除以 world size，并将结果写回各参数梯度。

所有组使用相同的 buffer 布局、同步时机和优化器更新顺序。该设计避免原生 DDP bucket 与逐参数 CCDL 通信之间的不公平比较。主实验不声称测量反向计算与通信重叠收益；生产化 DDP communication hook 适配留作后续工作。

另设独立通信微基准，用来分离量化、通信和反量化成本。

## 主实验矩阵

| 配置 | 通信格式 | Top-K | Group size | 舍入 |
|---|---:|---:|---:|---|
| NCCL-FP32 | FP32 | 不适用 | 不适用 | 不适用 |
| CCDL-INT8-K0 | INT8 | 0 | 64 | 确定性 |
| CCDL-INT8-K2 | INT8 | 2 | 64 | 确定性 |
| CCDL-INT4-K0 | INT4 | 0 | 64 | 确定性 |
| CCDL-INT4-K2 | INT4 | 2 | 64 | 确定性 |

每个配置使用 3 个固定随机种子，共 15 次完整训练。只有当 INT4 出现无法稳定收敛的证据时，才增加随机舍入诊断实验；该诊断不会混入首轮主对照统计。

## 训练协议与公平性

- 所有配置共享模型初始化、数据划分、每个 epoch 的样本顺序、全局 batch size、优化器、权重衰减和学习率调度。
- 使用标准 CIFAR-10 数据增强；验证集不使用随机增强。
- 每个随机种子在所有通信配置间一一对应。
- 正式运行前固定并记录依赖版本、CUDA、驱动、NCCL、GPU 拓扑和 CCDL 源码摘要。
- 不把数据下载、首次编译、dataloader 初始化和前 20 个训练步骤计入稳态吞吐统计。
- 每次验证在所有 rank 同步后进行，验证指标按完整验证集聚合。

## 收敛定义

对每个随机种子，先获得对应 NCCL-FP32 基线的最终验证 Top-1 精度。量化配置的目标阈值定义为：

`该 seed 的 NCCL-FP32 最终验证 Top-1 × 99%`。

量化配置首次达到该阈值，并连续 5 个 epoch 不低于该阈值时，视为收敛。记录：

- 首次满足条件的 epoch；
- 对应累计 optimizer steps；
- 从正式训练开始计算的墙钟时间。

若 200 epochs 内未满足条件，则标记为未收敛，不进行外推。最终报告逐 seed 数值以及三种子的均值和标准差。

## 通信微基准

消息大小覆盖 1、4、16、64、256 MB。每个配置执行预热和足够次数的正式重复，使用 CUDA Event 测量 GPU 时间，并报告：

- P50/P95 延迟；
- 算法带宽和总线带宽；
- 量化、通信、反量化及总时间；
- 实际量化字节数与压缩率；
- 量化前后相对 L2、RMSE、最大绝对误差。

基线与 CCDL 使用相同输入和同步边界。张量初始化或无关的 `copy_` 不计入通信延迟。计时前后执行必要同步，避免把异步工作错误归入其他阶段。

## 训练期指标

每一步采集：

- forward、backward、gradient sync、optimizer 和 total step time；
- images/s；
- 梯度范数；
- 量化前后梯度相对 L2 误差；
- NaN/Inf 状态；
- 峰值 GPU 显存。

每个 epoch 采集：

- 训练 loss 与训练 Top-1；
- 验证 loss 与验证 Top-1；
- epoch 墙钟时间与累计 optimizer steps。

最终精度同时报告最佳验证 Top-1、最后一个 epoch 的 Top-1 和最后 5 个 epoch 的平均 Top-1。

## 前置验证与失败处理

正式训练前必须依次通过：

1. CCDL CUDA 扩展导入与版本记录。
2. INT4/INT8、Top-K 0/2 的单卡 quantize-dequantize round-trip。
3. 双卡 CCDL all-reduce 与 FP32 参考值的误差检查。
4. 每个配置的短程训练 smoke test，检查 loss 下降、无 NaN/Inf、进程正常退出。

任何正式运行失败都保存配置、日志、最后 checkpoint 和错误上下文。同一配置不得静默跳过。若发现 CCDL 实现缺陷，应先记录复现用例并修复，再从相同 checkpoint 或完整重跑，报告中区分修复前后的结果。

## 非目标

- 本阶段不实现或评测语言模型。
- 本阶段不以 DDP communication hook 的计算通信重叠作为主结论。
- 不用单次运行、最佳 seed 或合成 TinyNet 结果代替完整复现。
- 不把理论压缩率直接表述为实际端到端加速。
