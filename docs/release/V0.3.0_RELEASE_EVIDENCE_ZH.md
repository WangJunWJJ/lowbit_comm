## 4. A6000 通信微基准

统一口径：每 rank `16,777,216` 个 FP16 元素，即 32 MiB；每种路径预热
3 次、测量 20 次；Native 与 compressed 交替运行 3 轮并取中位数。

| world size | Native 中位数 | Native in-place | compressed 中位数 | 相对 Native in-place |
| --- | ---: | ---: | ---: | ---: |
| 2 | 3.2968 ms | 3.2190 ms | 2.5664 ms | +25.43% |
| 4 | 7.2266 ms | 7.1320 ms | 5.2239 ms | +36.53% |

这是通信操作微基准，不等价于端到端模型训练吞吐提升。端到端收益仍取决于
bucket 大小、计算通信重叠率、模型结构、数据流水线和网络拓扑。

## 5. 双机语义门禁

两台 A6000 服务器通过 `eno2` 通信，验证时设置：

- `NCCL_IB_DISABLE=1`
- `NCCL_SOCKET_IFNAME=eno2`
- `GLOO_SOCKET_IFNAME=eno2`

| 配置 | 拓扑签名 | 最大绝对误差 |
| --- | --- | ---: |
| 双机 4 ranks | `node_ids=0,0,1,1` | 0 |
| 双机 8 ranks | `node_ids=0,0,0,0,1,1,1,1` | 0 |

该门禁证明通用 node 分组、local reduce、leader reduce 与 local broadcast
的顺序和数值语义正确。由于当前 `eno2` 为 1 GbE 且 RDMA fabric 未互通，结果
不用于宣称双机性能收益。

0.3.0 已通过当前计划要求的干净克隆、wheel、单机 2/4 卡、双机 4/8 rank

其他提交覆盖本证据对应的代码；若生产代码变化，必须重新执行发布门禁并更新证据。
